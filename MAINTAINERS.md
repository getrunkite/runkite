## Responsibilities

The maintainer reviews contributions, makes project scope and compatibility
decisions, manages releases and coordinates security fixes. Contributors can
help with code, tests, documentation, reproductions, design reviews and issue
triage without receiving write access.

Use public GitHub issues and pull requests for ordinary project work. Follow
[CONTRIBUTING.md](CONTRIBUTING.md) for contribution and testing expectations.
Report vulnerabilities through [SECURITY.md](SECURITY.md), rather than a public
issue. The security policy's support scope and absence of a formal response SLA
are unchanged.

## Becoming a committer or maintainer

Anyone may nominate a willing contributor, including themselves, using the
process in [GOVERNANCE.md](GOVERNANCE.md#committer-and-maintainer-nominations).
Appointment requires the nominee's explicit consent, a recorded decision and an
update to this file. Repository access, release access and credentials are
separate permissions and must be explicitly granted for the agreed scope.

An appointment should list the person's public handle, agreed responsibilities
and review or release scope. Publish an email address only with that person's
consent. Keep this file and `CODEOWNERS` aligned with the responsibilities that
have actually been accepted.

## Stepping back

A maintainer or committer may step back by notifying the maintainer and, where
practical, opening a pull request to update this list and hand over open work.
Access changes must be handled separately by an authorized repository or
organization administrator. A documentation edit alone cannot revoke or
transfer access, repository ownership or other project assets.
