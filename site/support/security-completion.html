Govern

Security operations

Current source after v0.6.1 adds opt-in review authority, evidence delivery and credential lifecycle controls around the existing connector gate.

Unreleased source only. Published v0.6.1 binaries and runner packages do not contain these additions. Read the upgrade procedure before enabling them. No exactly-once external effects or universal sandbox compatibility is claimed.

Review the exact operation

policy.approvals.required_approvals defaults to one and accepts one through five. exclude_requester excludes the exact immutable requester. Either strict option requires authenticated reviewer identities; exclusion also requires a known requester. Policy must first hold the operation. These options do not turn every allowed call into an approval.

Admin Pending and tenant Review show requester, approval_count/required_approvals, exact reviewer history and revisions. A successful partial vote says Review recorded and remains pending. It does not tell the app to continue. Duplicate requests from the same identity do not create extra votes. Stable identity-provider accounts remain the operator's responsibility.

Managed approvals match arguments, original run incarnation/generation, configured connector target, policy-v1- revision and optional tool-v1- schema revision. mcp.pin_tools: true discovers the requested MCP tool contract and rechecks it at dispatch. New optional contracts use target-v2-; existing descriptors retain v1. A schema hash does not pin implementation. policy.webhook.revision represents a declared remote PDP contract, not remote attestation.

Historical managed rows missing supported revisions need resubmission and fresh review. Standalone tool decisions still create no managed run, kill switch or budget controls. A changed standalone separation/quorum plan requires fresh review, including status polling of old decisions.

Deliver evidence without retrying tools

Set policy.action_export with name, HTTPS url, optional HMAC secret_ref and max_attempts (default 10, at most 100), plus audit_required and action_evidence. Only literal-loopback test HTTP accepts allow_insecure_loopback. URLs cannot include userinfo, query strings or fragments.

Each typed action/event metadata delivery is inserted with its SQL action transaction. A failed outbox write blocks protected dispatch before effects and preserves approval. The asynchronous sender uses stable delivery IDs and existing HMAC headers. A lost acknowledgement can resend the same ID; receivers must deduplicate it and reconstruct event order by action/sequence. This is at-least-once delivery, distinct from best-effort decision hooks.

Admin Evidence deliveries requires an explicit tenant. Filter by sink and pending/delivered/dead-letter state. A retry queues that existing evidence delivery only. It does not create a run, consume approval or execute a tool. Paging uses bounded offsets and can shift while rows update.

Effective sink identity hashes logical name, exact URL and schema. A changed destination gets a different queue; removed destination queues stay held. Restore the exact old destination to drain it. Deliveries survive action/run pruning and require operator capacity and explicit retention planning.

Lease credentials to a trusted consumer

Top-level credential_leases registers fixed Vault database roles, consumers and TTL ceilings. A connector uses auth.type: vault_database and a registered credential_binding. Vault keeps authentication, secrets-engine policy, encryption and revocation authority. Runkite is not another vault.

Only an authorized managed dispatch can issue a database lease. The fixed external MCP executor receives its PostgreSQL username/password privately as HTTP Basic credentials; neither the agent, runner session, tool arguments nor Admin receives those values. Initialization/schema discovery do not issue credentials. Ordinary bearer-only MCP servers need a credential-aware adapter.

Admin Credential leases selects an explicit tenant, shows metadata and permits server-checked manual renewal/revocation. Tenant Review reads its own metadata only. Cleanup handles remain privately encrypted outside public JSON. Opaque credential references link from action evidence to lifecycle detail.

Mount process-owned regular mode-0600 keyring and Vault token files. Symlinks are rejected. All replicas need the same retained keys; preserve old keys and retired provider bindings until old leases have confirmed cleanup. Vault must enforce role max_ttl. Actual returned TTL bounds the callback; manual renewal does not extend that released callback, and there is no automatic renewal loop.

issuance_unknown, renewal_unknown and revocation_unknown remain uncertain. A lost issuance response may also lose its handle. Do not repeat issuance or a tool to hide uncertainty. Investigate Vault audit/database state. Passing an estimated expiry is not provider-confirmed revocation, and revocation cannot undo a completed query or terminate every pre-existing session.

Separate fleet authority from workload containment

Execution pools select exact tenant/agent/framework membership and independently credentialed queues. A pool is not isolation between hostile agents inside its trusted worker. The optional Helm egress profile requires proxy-only runners, explicit allowed destinations and an enforcing CNI.

The experimental external OpenShell 0.1.8 profile keeps the trusted worker outside an explicit JSONL workload. It requires immutable image/policy configuration and uses incarnation-bound launch intents/receipts. An uncertain launch is not automatically repeated. Existing SDK workers do not become compatible or sandboxed by setting a pool flag. Unit tests and rendered manifests do not qualify runtime or CNI enforcement.

Actual disposable qualification passed: an installed Python runner, real SQLite plane and pooled worker completed five external OpenShell 0.1.8 lifecycle cases with Landlock hard_requirement, parent restart, receipt reclaim, uncertain-intent refusal, cancellation and confirmed cleanup. Separately, 10 chart egress cases passed on kind 0.33.0/Kubernetes 1.37.0 with default kindnet. This does not qualify unchanged SDKs, external multi-replica workloads, every runtime/kernel/CNI, cloud metadata or live providers. The bridge remains experimental and opt-in. See the qualification record.

Isolated-workload spend boundary: the experimental JSONL protocol has no model/token-usage or spend-settlement contract. Zero recorded spend does not mean no model calls or cost occurred. Managed admission still applies, but token/USD totals cannot cover unreported workload usage. Use external provider accounting and limits. Native SDK adapters' usage reporting is separate.
