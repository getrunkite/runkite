Security

Governance of the plane: who can run what, with which connectors, with an audit trail.

What the plane enforces

  • Client auth (API key / JWT) and route-level read/write/admin.
  • Optional agents:<id>:run grants on run-create.
  • Connector policy deny + durable audit (SQL backends).
  • Fail-closed serve: production refuses an insecure posture.

Tenancy

Flat tenant_id scope today — not a full org/team hierarchy. Checkpoint isolation is by key prefix. With runner tokens, configure RUNNER_TENANTS_* per kind.

What the plane does not see

Raw LLM prompts/completions (unless you add your own proxy), and framework-native tools that bypass connectors.
