Engineering notes

How the control plane behaves when a runner is reclaimed, a stream starts before enqueue, serve would start insecure, a job crash-loops, concurrent runs share a budget, or Postgres RLS cannot grant itself. Failure modes and the code that closes them. Not a second architecture overview.

Current-source integrations (Unreleased)

The source guide is the single developer entry point. The integration and qualification checklist records the required feature paths, public review references and combined gates. Merge and publication status are maintained separately. A source guide does not change published v0.9.0 packages.

  • Assignment identity protocol 1 and the transport and lifecycle contract: exact client echoes, immutable-record fences, record-scoped events/cancellation, legacy receipt handling and Kafka's explicit non-atomic compatibility boundary. Original-record finalization adds SQL accounting migration 23 (Postgres/SQLite) or 24 (MySQL), record-bound reservations and hook claims, with no guessed legacy backfill. Native qualification is tracked separately from source implementation.
  • Langfuse OTLP recipe and exporter and receiver boundary: existing exporters, exact HTTP encodings, asynchronous persistence and metadata/data-access limits. Native qualification is recorded separately from wire acceptance.
  • Tools-only connector profile and method and target contract: opt-in inbound methods, narrowed initialize capabilities, v4 target binding and coordinated rollout. Arbitrary tool results and SDK upstream negotiation remain separate boundaries.
  • Static graph schema recovery and publisher/store contract: cached Python static reports, atomic existing-bootstrap recovery, independent bounded rounds and old-plane compatibility. Useful/partial reports, MCP session snapshots and unknown freshness remain unchanged.
  • OpenShell effective-policy qualification and snapshot and checker contract: optional checkout-only comparison of current/loaded configuration around a fresh provider-free fixture. Local macOS passed; inspect the Linux workflow's actual current result separately. No production enforcement change, atomic exec fence or continuous-kernel proof.
  • RFE #47 combined runtime qualification and fixture-hardening rationale: existing two-plane/TLS/OpenShell composition, deliberate child environments, structured acceptance and worker-cancellation absence before final cleanup. Historical passes, current evidence and independent RFE #52 assessment remain distinct.
  • Advisory MCP schemas and configured profiles: bounded discovery, session snapshots, explicit unknowns and no runtime attestation.
  • Scoped specialist authority: exact grants, session authority binding and durable run-reference preconditions; agent-wide observation and retention limits.
  • Opaque metadata preservation: actual Admin transport, exact record/tenant selection and create/edit modes, SQL precision and MySQL/Mongo limits, without a merge or concurrent-edit guard.
  • Cron retained-run visibility and tenant routing: exact tenant/incarnation reads, read-only retained snapshots and shared schedule-thread selection that preserves owned legacy history. Named-tenant routing requires a coordinated cron-writer upgrade. Snapshot links expose no live SSE, cancel or child-run navigation; they do not add a stream incarnation fence or a fire ledger.
  • Cron calendar preview and parser and projection contract: independent opt-in read cost, one UTC computation snapshot, explicit timezone/outcome states and relative-interval unavailability. Separate parser/interval liveness fixes add no dispatch guarantee or global relative phase.
  • Offline static policy fixtures: current-engine decisions with strict input and no deployment configuration or service access.
  • Exact policy identities: raw positive matching and Admin tool-array serialization, conservative restrictive scopes, exact cache tuples and coordinated review/continuation rollout.
  • Langflow caller recipe and native-client evidence: baseline and run-only scoped profiles passed separately with a real local plane and Python worker; no UI/model-loop or REST observation proof.
  • promptfoo provider recipe and delivery and evaluator contract: one create attempt, private durable intent, qualified outer-retry guard and bounded read recovery, with separate broad and scoped scripted-worker receipts.
  • AG-UI text recipe and shared lifecycle evidence: official encoder/client, app ownership, durable finish, replay replacement, detach and authenticated Stop.

Demand-led caller recipes and wider runtime features stay deferred. These slices reuse existing run, connector, policy and frontend boundaries. They add no upstream certification, installer or embedded external platform.

  • 1 · Generation fencing: A stale runner cannot overwrite the winner after reclaim.
  • 2 · Subscribe-before-enqueue: Listen on the event broker before dispatch so early tokens are not lost.
  • 3 · createRunCtx / fail-closed serve: One admission funnel; production serve refuses an insecure posture.
  • 4 · Poison pill / reclaim ceiling: Stop dispatch at the ceiling, then acknowledge only after durable completion and finalization.
  • 5 · Optimistic spend holds: Reserve an estimate at create time so concurrent runs can't all pass a terminal-only budget check at once.
  • 6 · The RLS grant that can't grant itself: A Postgres 16 circular-grant gotcha that only shows up on a non-superuser DSN.
  • 7 · Managed AI SDK receipts: Commit native history before success; recover a committed turn without repeating model or tool work.
  • 8 · Runtime hardening (v0.6.0, Markdown): Exact policy arguments, fresh approval review, generation-fenced queue release, confirmed session revocation and bounded SDK/Admin delivery. Includes the design choices, source paths, upgrade requirements and regression evidence for contributors.
  • 9 · Atomic results and exact identities (v0.6.0, Markdown): Cache completion and metering, exact parent ownership, encoded runner identities and fail-closed native checkpoint keys. Explains transaction reuse, rejected alternatives, history continuity and operator boundaries. The Unreleased enqueue result fence explains why a failed acknowledgement must preserve a committed result or admitted worker.
  • 10 · Local HA recovery validation (v0.6.0, Markdown): Separates steady load from bounded cache, cancel, process-loss reclaim and retained-stream checks. Explains proxy checkpoint fixtures, literal poison identities, lease-preserving failures, atomic timeout completion, hook observer ordering, synthetic usage, measured rehearsal results and broader HA evidence limits.
  • 11 · Parent authority and secret-safe policy decisions (Markdown): Parent-derived delegation, required audit, safe provider diagnostics, credential alias redaction, compatibility and regression proofs. Explains the boundaries that remain outside this patch.
  • 12 · Managed connector action evidence (v0.7.0, Markdown): Why intent, response and business effects differ. Covers atomic approval consumption, original run identity, late observations, unknown outcomes, metadata-only retention, retained checkpoint identity/ordering corrections and regression proofs.
  • 13 · Tenant-scoped review (v0.7.0, Markdown): Separate review permissions, trusted tenant scope, argument visibility, isolated sessions, fixed expiry and SQL/API regression proofs.
  • 14 · Target-bound approvals (v0.7.0, Markdown): Bind managed approval authority to a configured connector target, pin the request snapshot through dispatch and require fresh review after changes. Covers secret-value exclusions, remote implementation limits, SQL migrations and regression proofs.

Retry safety and operator workflow (v0.9.0)

The checkout-only Trinity specialist boundary explains a fixed stdio caller, private immutable intent, REST-only retry observation and the distinction between source configuration, real Runkite protocol tests and native Trinity runtime execution.
