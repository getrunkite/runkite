Govern

Grants & HITL

Who may use which connector/tool — and when a human must approve before a side effect proceeds.

What it is

Grants are durable allow rules (tenant/agent/connector). Mandatory HITL forces matching tool calls to pending even when a grant would allow. Pending is the operator queue to approve or deny.

Why it is here

Secrets and side effects must not rely on “the agent was careful.” Governance sits on the plane next to minting and audit.

How to implement

  1. Define connector policy / grants (config defaults + Admin overlays on SQL).
  2. Add mandatory HITL rules for high-risk tools.
  3. Run an agent that hits a gated tool — status becomes interrupted / pending.
  4. Admin → Pending → approve or deny; agent retries the tool call after approve.

What to expect

  • Deny — tool never reaches the downstream connector.
  • Pending — operator must act; approve is one-shot for the next matching call.
  • Audit — decisions are queryable on SQL backends.
