Connect · Unreleased checkout recipe

Langflow MCP caller

Keep the Langflow flow and let its MCP Tools component call one specialist on your self-hosted Runkite plane.

Only the specialist creates a Runkite managed run. Langflow keeps its conversation, application and agent loop. No Langflow runtime or frontend is embedded in Runkite.

Prepare authority

Register a working Runkite agent and runner, initially the provider-free echo_agent. Use the exact HTTPS endpoint https://<your-plane>/mcp and configure MCP session affinity on a multi-replica deployment.

  • Published v0.9.0: a dedicated tenant and trusted server-side caller key with read and write. The key has broader tenant authority than one specialist. Do not use Admin.
  • Unreleased scoped source: agents:echo_agent:run admits MCP discovery/invocation. The separate agents:echo_agent:observe permits exact run GET/wait for application recovery. It grants no broad lists, thread history, store, stream, cancel or delete. Published v0.9.0 does not include this scoped contract.

Keep one trusted caller and a dedicated tenant. Agent-scoped observation is not requester-private ownership. Choosing a tool in Langflow does not narrow a broad Runkite credential.

Connect MCP Tools

  1. In Langflow, store the complete Bearer <caller-key> value in a Credential global variable named RUNKITE_AUTHORIZATION.
  2. Open Settings > MCP Servers > Add MCP Server, choose HTTP/SSE, and set the URL to your plane's /mcp endpoint.
  3. Set header Authorization to RUNKITE_AUTHORIZATION, keep TLS verification enabled, and save.
  4. Drag the server from the MCP sidebar into the flow and select echo_agent. To use it with an Agent, enable Tool Mode and connect Toolset to Tools.

For a manual provider-free smoke, leave Tool Mode off and supply message, a saved run_id and optional thread_id. Leave input unset when using a message: a supplied input object overrides it. Validate field binding and output rendering in your own Langflow deployment.

Keep the destination and credential in trusted server configuration. A private plane host may need Langflow's operator-controlled SSRF host allowlist. See the official Langflow MCP client guide and the checkout application/operator recipe.

Retain intent before retries

Persist the exact agent, input, thread and unique run ID before the first invocation. Reuse that operation after a lost response. A model remembering an ID is insufficient, and the stock MCP Tools component does not supply a durable Runkite receipt store. Unattended tool use needs application code that injects and enforces the saved values. The pinned native client can retry after a session failure.

Retained matching calls observe the same run; intentional new turns need new saved IDs. Deleting the run ends retry protection. For background handles, use the existing REST create/get/wait API. With the scoped source feature, preserve the first raw run reference and send Runkite-Expected-Run-Reference on subsequent exact observation. Displayed tool text may omit that metadata.

Approvals and cancellation

Tool errors remain failures. Delivery timeout or disconnect leaves the execution outcome unknown. Pending connector review stays in Runkite's existing Review/Admin flow and is not auto-approved by Langflow. Stopping a request or deleting an MCP session does not prove worker cancellation or rollback. Explicit cancel requires separate operator/API authority.

Reconnect after permission or schema changes. Typed nested agent-input discovery is a separate feature; this qualification uses the generic MCP envelope.

What was qualified

On November 16, 2026, unmodified LFX 1.13.2 and MCP 1.30.0 passed a native headless test against a real local Runkite API and Python worker. Native discovery, header handling, schema conversion and tool invocation negotiated MCP 2025-11-25. Two intentional operations created exactly two managed runs and two worker assignments, including successful and failed-run retries. The test used the published read/write profile and made no provider calls.

This does not qualify the Langflow browser UI, server/project database, credential-variable UI, model loop or production proxy. The scoped profile needs a separate integrated-source run. See the recorded receipt and engineering boundary.
