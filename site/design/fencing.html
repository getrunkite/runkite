Engineering note · 1 of 7

A stale runner cannot win.

Reclaim gives the next attempt a higher generation. Heartbeats, event publication and completion check that exact attempt. The durable completion transaction prevents a superseded runner from replacing the current result.

The race that breaks queues

Runner A takes a job. Heartbeats stop (pause, partition, OOM). After ~6s the reclaim loop bumps generation and requeues. Runner B finishes successfully. Then A wakes up and tries to report success. 

t=0   A dequeues  generation=1
t=6   reclaim → B dequeues  generation=2  · B reports success
t=?   A recovers · ReportStatus(gen=1)

without fencing:  A’s late completion overwrites B  →  corrupt final status
with fencing:     Ack(gen=1) rejected · Heartbeat returns superseded=true

What generation actually gates

  • Heartbeat: control plane answers with superseded: true; the runner cancels local work.
  • ReportStatus / Ack: non-current generation is ignored; the thread stays on B’s terminal state.
  • All StreamEvents: the bridge checks the message's generation against the live assignment before each publish, including progress events.

The queue check and broker publish are separate operations. Reclaim can happen between them, so raw nonterminal output remains advisory during reclaim. Since v0.6.0, run SSE, thread SSE and WebSocket terminals pass the same durable completion fence; a superseded terminal cannot finish a replacement attempt. Clients must preserve attempt boundaries instead of combining already displayed text. /wait and stored output remain authoritative, and Admin Run Detail reloads the record when its stream ends.

Zero is an exact generation

Since v0.5.6, 0 matches only an actual generation-zero assignment. It cannot borrow a later attempt's generation or bypass Renew/Ack. New assignments start at 1. Upgrade custom and older runners to echo the assignment's generation on every run-bound RPC and internal HTTP call.

Complete before acknowledging

ReportStatus commits the current attempt's status and output before Ack removes its queue lease. Failed database writes leave the job recoverable. A lost response can retry an already committed result without writing it twice. Stream delivery failure is a delivery error, not a replacement agent error.

Source: StreamEvents / ReportStatus, CompleteRun.

Same contract across transports

Redis bumps a hand-rolled counter on reclaim. NATS reuses JetStream NumDelivered. Kafka stores generation in the compacted state topic and bumps it on every re-produce. The Runner Protocol surface is identical: carry generation on every bound RPC. The single-instance in-process queue uses the same exact-match rule. Transport support tiers remain as documented.

Think boarding-pass versions: if reclaim reissued seat gen=2, your gen=1 pass cannot board, even if you arrive late with a smile.
