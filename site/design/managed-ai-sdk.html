Commit the turn before success.

A managed AI SDK runner can finish a tool and persist its native conversation, then crash before the plane sees completion. A saved current-run receipt lets the next attempt deliver that result without executing the tool again.

This note describes the TypeScript AI SDK backend that ships in v0.5.8 runkite-runner. The app-owned tool-decision helper remains a separate option. See SDK integrations for availability and the request-path change.

Two completion boundaries

app → Runkite run → native ToolLoopAgent
                      → model/tool messages
                      → CAS state + current-run receipt
                      → final values + native UI finish
                      → end / ReportStatus
plane → durable current-attempt completion → finalization → Ack

The runner commits native state through the existing opaque HTTP API before publishing success. The plane separately commits the run's current-attempt outcome before acknowledging its queue lease. These are different transactions; the recovery design must handle a process disappearing between them.

The crash after PUT

Native state contains full model/tool message history and a receipt for the last successful turn. The receipt binds the run ID and canonical new-turn input inside that thread's agent-scoped state. A reclaimed assignment loads it. If that run and input match, it replays committed UI/text events and final values with the new attempt's identity. It does not call the factory, model or tool again.

The next ordinary user turn instead restores native message history and executes a new SDK invocation. Old usage is not added to the new turn. The existing durable run-completion keys prevent a recovered turn from being charged twice.

What CAS protects

Reads require the expected framework, agent and strong numeric ETag. Writes use If-Match, or create-only If-None-Match: *. Tenant, runner kind, run ID and generation use the existing bound headers. A conflict or an uncertain commit leaves completion recoverable instead of silently overwriting another writer's history. A strict JSON/Unicode codec refuses unsupported values. The Go plane stores opaque bytes and does not import the SDK or its schema.

The boundary before commit

If a tool's external write succeeds but the process dies before the state commit, the next attempt cannot infer that write from an absent receipt. It may execute again. Use a downstream idempotency key or the application's existing outbox. A local receipt does not provide exactly-once remote effects.

Interruptions retain only previously committed turns. Native approval/resume, partial-turn restoration, binary/client/provider tools, streaming tool outputs, time travel and whole-run caching are outside the initial profile. The older generic Python adapters do not acquire this receipt/CAS contract merely by using the same opaque endpoint.

UI delivery is another boundary

Ordinary progress can stream before state commits. Native UI finish waits for that commit, and the app bridge waits for the plane's durable /wait result with matching attempt/message identity. Raw SSE stays advisory during reclaim. If a new attempt starts after text has rendered, the bridge reports a delivery error rather than combining attempts. The app keeps authentication, chat ownership and the server-side plane key.

Proof and source

The subprocess suite kills a real runner after the plane accepts PUT but before the runner receives its response. Reclaim advances generation; the next runner completes from the receipt with one original tool effect and one usage charge. The suite has SQLite and Postgres + Redis profiles, each with one plane process. It does not establish multi-replica HA behavior.

  • AiSdkAdapter.executeBound: native loop, receipt replay and event ordering.
  • AiSdkState.load/save: bound HTTP, strict codec and conditional writes.
  • Subprocess integration tests: make test-managed-ai-sdk.
