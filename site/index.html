Scenario · why a plane

Three agents. Two frameworks. One shared connector.

When a single LangGraph script stops being enough: a LangGraph coordinator and worker, plus a second runner kind when you need another framework — same connector secret, not three .env copies.

Without a control plane

Three scripts, three copies of the secret

Each agent process owns its own env, HITL, and logs. Delegation is ad hoc HTTP. Ops is SSH + grep.

LangGraph · coordinator → GITHUB_TOKEN in .env
LangGraph · worker → GITHUB_TOKEN again
CrewAI / LangGraph.js → same secret, third place
A2A? → custom HTTP glue per pair
Ops? → 3 dashboards, 3 log streams

With Runkite

One plane. Run-bound sessions. Shared Admin.

Clients hit Agent Protocol. Runners pull jobs. Connectors mint credentials from the assignment — not from forged headers.

Client / SDK → Control plane → connector session
CP → LangGraph runner · coordinator + worker
CP → CrewAI / LangGraph.js runner
  • 1
    Shared connector, not shared .env Configure once in the plane. Agents call get_connector_session / getConnectorSession under run-binding and optional grants.
  • 2
    Agent-to-agent on the same queue Coordinator delegates with call_agent / callAgent — depth limits, cancel cascade, parent/child visible in Admin.
  • 3
    Two frameworks, one ops surface HITL, kill/pause, audit, and threads live on the plane whether the graph is LangGraph or another runner.

In Admin you should see parent/child runs for A2A and one connector grant reused across agents — not three pasted tokens.

When not to use Runkite

One agent, one laptop, exploring prompts

Stay in LangGraph / CrewAI / your notebook. A control plane earns its keep when you need a shared HTTP API, HITL that isn’t glued to one process, shared connectors, or more than one runner kind. If that’s not you yet — skip the plane.

  • Prototyping a single graph with local state
  • No shared secrets, no second agent, no ops surface needed
  • You need a managed cloud plane today (Runkite is self-host first)

Try it · 5 minutes

Compose up → echo → HITL → done

Zero-dependency stack: control plane + runner, SQLite + in-memory. No Go toolchain, no .env. Needs Docker and python3 (for the curl JSON one-liners). Laptop demo only — not internet-facing.

Compose is up

Plane on :2026. Runner waiting. Admin open.

Echo agent

POST a run. Wait. See the echoed message.

HITL interrupt

approval_agent pauses — status interrupted.

You approve

Resume with {"command":{"resume":true}}. Run completes.

~/runkite 
# needs Docker · first build takes a few minutes
git clone https://github.com/getrunkite/runkite && cd runkite
docker compose -f docker-compose.dev.yml up -d --build
curl -sf http://localhost:2026/readyz && echo OK
# Admin → http://localhost:2026/admin/
echo_agent 
# 1) Echo
BASE=http://localhost:2026
THREAD=$(curl -sf -X POST "$BASE/threads" -H 'Content-Type: application/json' -d '{}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["thread_id"])')
curl -sf -X POST "$BASE/threads/$THREAD/runs/wait" \
  -H 'Content-Type: application/json' \
  -d '{"agent_id":"echo_agent","input":{"messages":[{"role":"user","content":"Hello, Runkite!"}]}}' \
  | python3 -m json.tool
# → status success · ai content is the same string: "Hello, Runkite!"
approval_agent · HITL 
# 2) Interrupt — new thread (don't reuse echo's THREAD)
BASE=http://localhost:2026
THREAD=$(curl -sf -X POST "$BASE/threads" -H 'Content-Type: application/json' -d '{}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["thread_id"])')
# SSE lines stream here; look for "interrupted", then Ctrl-C and run step 3
curl -sf -N -X POST "$BASE/threads/$THREAD/runs/stream" \
  -H 'Content-Type: application/json' \
  -d '{"agent_id":"approval_agent","input":{"messages":[{"role":"user","content":"send the email"}]}}'

# 3) Approve / resume
curl -sf -X POST "$BASE/threads/$THREAD/runs/wait" \
  -H 'Content-Type: application/json' \
  -d '{"agent_id":"approval_agent","command":{"resume":true}}' \
  | python3 -m json.tool
# → status success · "Email sent to alice@example.com successfully!"
